Post-beta modularization plan · analysis & design only

Taking the monolith apart without moving a single frame.

ChartQuest's game is one self-contained 30,058-line HTML document whose entire runtime lives in a single 22,907-line <script>. The project already ships two working prototypes of the fix — ops/cq-ops.js and cq-track.js are authored standalone and spliced in, drift-gated, producing a byte-identical file. The blueprint generalizes that mechanism to the whole game.

01 — Current architecture

Ten script blocks. One of them is the whole game.

Block 3 holds market, movement, render, Finn, lessons, trade, boss, cinematics and audio in one contiguous span. Blocks 2 and 6–10 are the only real seams — the operational foundation, and the append-only IIFEs that bolt features on by patching the core at runtime.

02 — Dependency graph

Four spines hold the whole thing together.

turtle, trade, COLOR and CFG are read from nearly everywhere. That is what makes a naive file-split dangerous — and why the entangled subsystems are sequenced last. The one clean boundary that exists today is the append-only seam at the bottom, which patches the core rather than editing it.

03 — Recommended module structure

Author in files. Splice into one document. Ship byte-identical.

The single-file design law stays intact: the game still runs from file:// with no external script. Modularity is authoring-time; a build step reassembles the exact same bytes — which is precisely why the player can never tell it happened. This already works for two modules (ops/cq-ops.js via sync_ops.py, cq-track.js via sync_track.py); the blueprint generalizes it.

The merge-conflict case

Hard git data over 190 commits.

The top-3 churn files are one file, mirrored 3×

index.html (108) · chart-quest.html (107) · website/game.html (57). Every logical change is a 3-file simultaneous rewrite under gate #8.

  • Documented scars: "three concurrent sessions, one outstanding conflict"; a self-caused clobber; two retractions; a stale analytics client shipped to testers — and gate #20 was born to catch cross-session drift.
  • After Tier-1: mirrors become generated output (removes 165 of the top-3's commits from hand-merge), edits go module-local. Estimated ~80–90% fewer same-file hunk collisions.
  • The scope trap closes per-module: one window.* write, zero new top-level names — a cross-session merge can't reintroduce a silent duplicate-declaration crash.
Non-negotiable constraints preserved throughout — single self-contained document · byte-identical mirror (gate #8) · no new top-level names · 9 protected systems frozen · 21 gates stay green · save keys byte-frozen · the Trade Clock never re-couples to traversal.
