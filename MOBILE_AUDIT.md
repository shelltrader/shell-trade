# ChartQuest — Mobile Audit

**Date:** 2026-07-10 · **Scope:** `website/` (landing, game shell, embedded game, PWA)
**Verdict:** 8 P0 launch blockers found. **All 8 fixed.** 11 P1, 7 P2 — most fixed, the rest listed with rationale.

---

## How this was tested — and what that does NOT cover

Every number below is a real measurement taken in a Chromium browser driven against the
site, not an estimate. Viewports exercised: **360×800, 375×667, 390×844, 430×932, 820×1180,
and 844×390 (landscape)**.

**This is emulation, not devices.** The brief correctly says desktop emulation is not
sufficient. Specifically, the following could **not** be verified here and must be checked on
real hardware before release:

| Cannot verify in emulation | Why | Where it's checked |
|---|---|---|
| iOS Add-to-Home-Screen flow | No iOS Safari | Regression checklist §4 |
| iOS launch screens (splash) | Only iOS reads `apple-touch-startup-image` | §4 |
| `env(safe-area-inset-*)` values | Always `0px` without a notch | §5 |
| Real fullscreen | Headless Chrome has no window manager | §3 |
| `beforeinstallprompt` | Doesn't fire in this harness | §4 |
| `(pointer:coarse)` media query | Reports `fine` | §2 (mitigated, see P1-01) |
| 60fps / battery / GPU | No device thermals | §6 |

Also note: this harness reports `document.hidden === true`, which freezes `rAF`, CSS
transitions and IntersectionObserver. Several "failures" during the audit were that artifact,
not real bugs (e.g. the burger→X morph tested as broken until transitions were disabled).

## P0 — Launch blockers

### P0-01 · "Install to Home Screen" was completely unreachable ✅ FIXED
`window.cqInstall()` was defined in `website/index.html`, and `beforeinstallprompt` was
captured into a `deferred` variable — but **nothing on the page ever called it.** Measured:
`grep -c "cqInstall()" website/index.html` → **0**. The install prompt was captured and thrown
away on every visit. On iOS it was worse than unreachable: `beforeinstallprompt` never fires
there at all, so even a button would have done nothing.

**Fix:** real install buttons in the nav (desktop + mobile sheet), a full lifecycle
(`beforeinstallprompt` → native prompt; `appinstalled` → hide forever; `display-mode:standalone`
/ `navigator.standalone` → never show), and a designed iOS walkthrough sheet for the case where
no API exists. On touch devices the button always appears, so install is never a dead end.

### P0-02 · The game could not enter fullscreen on iPhone ✅ FIXED
The cause, in `website/play.html`:
```js
(el.requestFullscreen || el.webkitRequestFullscreen || function(){}).call(el);
```
On iPhone Safari **both** are `undefined` — the Fullscreen API exists there only for `<video>`.
So the expression fell through to `function(){}` and the button silently did nothing, forever,
with no error. That is the reported bug.

**Fix:** feature-detect properly, then branch honestly.

| Context | Behaviour |
|---|---|
| Installed PWA | Button hidden — there is no browser chrome to escape |
| Fullscreen API works | Real fullscreen + `screen.orientation.lock('portrait')` (fails silently off-Android) |
| iPhone Safari | Button opens the install sheet — installing *is* the only real fullscreen on iOS |

Also added: `fullscreenchange` + `webkitfullscreenchange` listeners (the label was permanently
desynced), promise-rejection handling (`requestFullscreen()` rejects without a gesture), and
`body.is-fs` to hide the top bar.

### P0-03 · The mobile menu was a `display` toggle, not a menu ✅ FIXED
Measured on the old build at 375×667:

| Check | Before |
|---|---|
| Animation | `display:none` → `flex` — **cannot be transitioned** |
| Backdrop | none |
| Body scroll lock | **none — the page scrolled behind the open menu** |
| Closes on Escape | no |
| Closes on outside tap | no |
| `aria-controls` | missing |
| Focus management | none |
| Safe area | none (hard-coded `top:66px`) |

**Fix:** animated sheet (transform + opacity, `visibility` delayed out), tappable blurred
backdrop, `position:fixed` body lock that **preserves and restores scroll position** (iOS
scrolls an `overflow:hidden` body), Escape + backdrop + link close, focus moved into the sheet
and returned to the burger, a focus trap, `aria-controls`/`aria-expanded`/dynamic `aria-label`,
burger→X morph, `100dvh` max-height with internal scroll, and notch/home-indicator padding.

### P0-04 · No iOS launch screens ✅ FIXED
Zero `apple-touch-startup-image` links. An installed PWA therefore flashed a **white screen on
every cold start** — the single most "this is a website" tell there is.
**Fix:** 11 device-exact splash images generated by `scripts/make_pwa_assets.py`.

### P0-05 · Maskable icons would be cropped by Android ✅ FIXED
The manifest declared `"purpose": "any maskable"` on **the same unpadded image**. Android masks
icons to a circle and only guarantees the middle 80%; the old art ran to the edges, so the mark
was clipped on most launchers.
**Fix:** separate `icon-maskable-{192,512}.png` with the mark inside the safe zone, and `any`
icons kept distinct.

### P0-06 · Unapproved procedural turtle shipped across the site ✅ FIXED
`website/assets/site.js` injected a hand-drawn SVG turtle (`#cq-turtle`, `window.cqTurtle`)
into the game loader, the play-bar, the install modal, `bosses.html` and `courses.html`. It
predates Finn and was never approved.
**Fix:** generator and sprite deleted; every mount replaced with the brand logomark, the app
icon, or the official `finn-hero.png`. Sweep result: **0 occurrences** of `data-turtle` /
`cq-turtle` / `cqTurtle` anywhere in `website/` except the in-game chart marker below (P2-04).

### P0-07 · No safe-area handling anywhere ✅ FIXED
`grep safe-area-inset website/*.html` → **0**, despite `viewport-fit=cover` being set. In a
standalone PWA the nav sat under the notch and the sticky CTA under the home indicator.
**Fix:** `env(safe-area-inset-*)` on the nav, menu sheet, sticky CTA, footer, install sheet,
play-bar, game frame and offline page.

### P0-08 · Landscape phone hid the Play button below the fold ✅ FIXED
At 844×390 the hero's `height:clamp(580px,94vh,960px)` floor (580px) plus the 66px sticky nav
exceeded the viewport. Measured `ctaBottom: 440` vs `vh: 390` — **the primary CTA was 50px
below the fold on a landscape phone.**
**Fix:** a `(orientation:landscape) and (max-height:520px)` block sizes the hero to
`calc(100dvh - 66px)` and drops the eyebrow/trust-line. Now `ctaBottom: 381` ≤ `390`.

## The 14-year-old test

> They install it from TikTok, play 10 minutes, close it. Tomorrow they tap the icon.

**Before:** they could not install it (P0-01). If they somehow did, it cold-started to a white
flash (P0-04) with a clipped icon (P0-05), the game could never go fullscreen on their iPhone
(P0-02), and the menu scrolled the page behind itself (P0-03).

**After:** the icon is a crisp candlestick mark, the app opens to a branded launch screen with
no browser chrome, the menu behaves like a native sheet, and fullscreen either works or tells
the truth about why it can't.

The remaining gap between "premium mobile game" and "website" is **P1-11** (canvas DPR) and
**P2-03** (paint cost) — both are frame-rate concerns that only a real device can settle.
